# ラムダ式・匿名クラスとは？

ラムダ式は、Java 8で導入された**「その場で処理を渡す」ための簡潔な記法**です。`Runnable`や`Comparator`のような**関数型インターフェース**（抽象メソッドを1つだけ持つインターフェース）を実装する際に、わざわざクラスを定義せずに済みます。

ラムダ式が登場する以前は、同じ目的のために**匿名クラス**（名前のないその場限りのクラス）が使われていました。既存コードで両方の書き方が混在していることが多く、**ラムダ式は匿名クラスの簡略記法である**という関係を理解しておくと読み替えがスムーズです。

### 🏭 イメージ：「その場限りの代打」

1. **関数型インターフェース（役割の定義）**
   - 「比較する」「実行する」といった**1つの仕事だけを定義したインターフェース**。
2. **匿名クラス（フルネームを名乗らない選手）**
   - `new Comparator<String>() { ... }`のように、その場でクラス本体を書いて実装する。**クラス名・インスタンス変数を持てる**。
3. **ラムダ式（もっと身軽な代打）**
   - `(a, b) -> ...`のように、**引数と処理内容だけ**を書けばよい。冗長なクラス定義が不要になる。

---

## ✨ 主な特徴

| 特徴 | 説明 |
| :--- | :--- |
| **関数型インターフェース限定** | ラムダ式は、抽象メソッドを1つだけ持つ**関数型インターフェース**（`@FunctionalInterface`）にのみ使える。 |
| **匿名クラスとの違い** | 匿名クラスは**独自のフィールドを持てる**が、ラムダ式は持てない（外部の変数を参照するのみ）。また匿名クラスは`this`が自分自身を指すが、ラムダ式の`this`は**外側のクラス**を指す。 |
| **標準の関数型インターフェース** | `Function`, `Predicate`, `Consumer`, `Supplier`等が`java.util.function`パッケージに用意されている。 |
| **メソッド参照** | 既存メソッドをそのまま渡す`ClassName::methodName`という、さらに簡潔な記法もある。 |

---

## 📝 代表的な構文

| 種類 | 構文 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| **匿名クラス** | `new Interface() { @Override ... }` | その場でインターフェースを実装するクラス本体を書く。 | |
| **ラムダ式** | `(引数) -> 処理`  | 引数と処理本体だけを書く簡潔な記法。 | `(a, b) -> a + b` |
| **引数なし** | `() -> 処理` | 引数を取らないラムダ式。 | `() -> System.out.println("Hi")` |
| **メソッド参照** | `ClassName::methodName` | 既存メソッドをそのままラムダとして渡す。 | `String::toUpperCase` |

### 🛠️ コード例

```java
import java.util.Comparator;

public class LambdaVsAnonymousExample {
    public static void main(String[] args) {
        // 匿名クラス（旧来の書き方）：クラス本体を丸ごと書く
        Comparator<String> byLengthOld = new Comparator<String>() {
            @Override
            public int compare(String a, String b) {
                return Integer.compare(a.length(), b.length());
            }
        };

        // ラムダ式（同じ処理を簡潔に）：引数と処理だけを書く
        Comparator<String> byLengthNew = (a, b) -> Integer.compare(a.length(), b.length());

        System.out.println(byLengthNew.compare("cat", "elephant")); // 負の値
    }
}
```

既存コードで`new Runnable() { ... }`のような匿名クラスを見つけたら、それを**ラムダ式に置き換えられないか**を考えると、モダンな書き方への理解が深まります。ただし、独自フィールドを持つ・複数の抽象メソッドを実装する場合はラムダ式に置き換えられない点に注意してください。
