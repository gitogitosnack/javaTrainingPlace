# recordとは？

`record`は、Java 14でプレビュー導入され、Java 16で正式機能となった**不変（immutable）データ保持クラス**を1行で定義できる構文です。

DTOやValue Object（値オブジェクト）を作るために必要だった`private final`フィールド・コンストラクタ・`getter`・`equals`・`hashCode`・`toString`といった**定型コードを、コンパイラが自動生成**してくれます。Lombokの`@Value`が担っていた役割の多くを、**言語標準の機能**として実現できるようになったイメージです。

### 🏭 イメージ：「自動で完成する型紙」

1. **フィールドの宣言だけで完成する**
   - `record Point(int x, int y) {}`と書くだけで、`x`・`y`を保持する不変クラスが完成する。
2. **勝手に生成されるもの**
   - コンストラクタ、`x()`・`y()`という**アクセサメソッド**（`getX()`ではなく`x()`という名前になる点に注意）、`equals()`、`hashCode()`、`toString()`が自動生成される。
3. **変更したければ新しいインスタンスを作る**
   - フィールドは`final`のため`setter`は存在しない。値を変えたい場合は**新しい`record`インスタンスを生成**する。

---

## ✨ 主な特徴

| 特徴 | 説明 |
| :--- | :--- |
| **不変性** | 全フィールドが自動的に`private final`になる。生成後の変更は不可能。 |
| **アクセサの命名規則** | 通常のクラスの`getName()`と異なり、`record`は`name()`という**フィールド名そのままのメソッド**になる。 |
| **`equals`/`hashCode`の自動実装** | 全フィールドの値が一致すれば`equals()`が`true`を返す（参照ではなく**値の等価性**で比較される）。 |
| **コンパクトコンストラクタ** | 通常のコンストラクタを省略しつつ、**バリデーション処理だけ**を追加で書くことができる。 |
| **継承不可** | `record`は暗黙的に`final`であり、他のクラスを継承できない（インターフェースの実装は可能）。 |

---

## 📝 代表的な構文

| 種類 | 構文 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| **基本定義** | `record Name(型 field1, 型 field2) {}` | フィールドを引数のように書くだけで完成する。 | |
| **コンパクトコンストラクタ** | `record Name(...) { Name { ... } }` | 生成時のバリデーションを追加する。 | |
| **独自メソッド追加** | `record`の本体にメソッドを追加 | 計算プロパティ等、通常のクラスと同様にメソッドを定義できる。 | |

### 🛠️ コード例

```java
public class RecordExample {
    // 1行でフィールド・コンストラクタ・アクセサ・equals/hashCode/toStringが完成
    record Point(int x, int y) {}

    public static void main(String[] args) {
        Point p1 = new Point(1, 2);
        Point p2 = new Point(1, 2);

        System.out.println(p1);           // Point[x=1, y=2] (自動生成されたtoString)
        System.out.println(p1.x());       // 1 (アクセサ。getX()ではない点に注意)
        System.out.println(p1.equals(p2)); // true (値が同じなら等しいと判定される)
    }
}
```

既存コードで、DTOクラスなのに`getter`だけがあり`setter`が存在しない小さなクラスを見つけたら、`record`で書き換えられる候補だと考えると設計改善につながります。
